# 全量 uni-app Vue 3 迁移需求

## 目标与范围

将 `D:\saven\miniprogram` 的 24 个用户侧页面及公共前端能力迁移至 `E:\sravxapp\sravx`，统一采用 uni-app Vue 3 语法，并保持微信小程序端现有可见功能与业务规则。原生小程序在验收前保留为回退参考，不删除、不发布替换。

本次只改客户端呈现和调用适配；不创建生产资源、不改小程序发布配置、不变更支付回调、不执行真实支付、退款或订单操作。

## 用户故事与验收标准

1. 目录与导航
   - 当用户进入新版小程序时，系统应提供首页、商品目录、搜索、商品详情、购物袋、订单和“我的”的完整页面导航。
   - 当用户切换底部导航时，系统应显示与原小程序相同的四个主入口：首页、购物袋、订单、我的。

2. 身份与账户
   - 当用户需要登录或授权手机号时，系统应通过微信小程序能力完成原有登录流程，且不在客户端日志、页面数据或仓库中暴露 OpenID、手机号、Token、session_key。
   - 当用户查看或编辑资料、会员、积分、优惠券、地址或剪刀信息时，系统应仅使用当前认证身份对应的数据。

3. 交易与售后
   - 当用户创建普通订单、积分订单、兑换礼品卡、取消订单、申请售后或提交物流信息时，系统应保留原有前端校验、幂等键和后端请求语义。
   - 当用户发起微信支付时，系统应仅调用经后端签发的支付参数，并使用 `uni.requestPayment`；客户端不得自行计算价格、库存、退款金额或支付状态。
   - 当用户申请退款时，系统应只提交申请，不在客户端承诺退款结果或金额。

4. 服务能力
   - 当迁移后的页面需要现有云函数时，系统应通过统一适配层调用既有安全入口；迁移期间不得在订单、库存、积分、礼品卡、退款或支付回调上双写。
   - 当迁移后的页面需要已验收的 HTTPS API 时，系统应复用当前 API 合约与合法域名，不能静默降级至不受控端点。

5. 体验与质量
   - 当网络失败、未登录、参数缺失或接口返回错误时，系统应展示用户可理解的提示，且不得卡死加载状态。
   - 当每个页面迁移完成时，系统应通过微信开发者工具编译、真机核心路径验证和与原生页面的功能核对。

## 非目标与边界

- 不迁移云函数、CloudRun、数据库、支付回调消费者或生产数据。
- 不以此次前端重构为由启用尚未放行的新服务器 API 功能。
- 不承诺、触发或模拟真实支付、退款、下单、物流或生产发布。
- 视觉沿用现有 Sravx 页面风格；不进行额外品牌重设计。

## 待验收信息

- 微信开发者工具与 HBuilderX 能否对该项目稳定编译。
- 当前测试环境是否允许调用 CloudBase 函数和 `https://api.sravxpet.com`。
- 各交易页面的测试账号、测试商品及非生产测试订单方式由业务负责人提供后再验证。
