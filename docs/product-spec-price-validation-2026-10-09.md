# 规格价格规则核验（2026-10-09，仅本地）

负责人要求以商品规格价格为主，首页展示最低规格价格，并要求商品编辑必填价格。

## 已实现

- 普通商品首页、列表与详情的起价从规格最低价计算；保留原始 `base_price`，不批量修改既有数据库数据。结构化商品从在售 SKU 的分价计算最低起价，不以库存数量改变起价。
- 网页和小程序共用价格解释，首页显示 `¥金额 起`。选中型号使用该型号自己的价格，缺价不回退到商品起价。
- 管理端新建/编辑规格价格默认为空，要求每个有效规格填写大于 0、最多两位小数的金额；商品起价只读并自动计算。SKU 编辑也拒绝缺价、零价及非法精度。
- 目标 API 对每个规格执行相同校验；无规格商品必须有有效商品价；存在规格自动标记为规格商品。保存商品起价取规格最低值，不相信单独传入的起价。
- 普通确认订单补传型号名称；目标订单接口优先查该规格的服务端价格，不使用客户端价格，规格缺价拒绝创建订单。没有开启或改变任何订单/支付迁移开关，旧云函数交易兼容性不据此认定完成。
- 历史明确零价读值保留，但新编辑保存要求正价；没有自动改写线上价格或制造缺失价格。

## 本地证据

- 后端全套测试 146 项通过，包括起价 SQL、保存校验及隔离订单价格测试。数据库调用使用测试桩，未创建真实订单。
- 前端六组测试共 26 项通过，包括最低规格价、缺价处理、选型价格、两端商品组件契约与库存守卫。
- 管理端类型检查及构建通过；拦截全部业务请求的浏览器编辑回归通过：缺价不能保存，两规格 2.50/1.25 自动产生起价 1.25，模拟保存保留各自规格价。现有图片、型号增删、发货信息和响应式检查仍通过。
- 为浏览器隔离验收，管理端构建临时使用 target 模式；未修改线上开关或环境配置。使用本机 Playwright/Chrome 替代不可用的 agent-browser。
- 微信小程序构建及配置检查通过（26 页面）；H5 构建通过。既有 H5 入口挂载问题仍未在本轮解决，不能将编译通过等同于网页运行验收；小程序真机与真实管理员保存仍待验收。
