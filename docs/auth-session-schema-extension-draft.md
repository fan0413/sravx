# 服务端会话账本结构扩展草案

更新：2026-09-10。目标库当前已按负责人批准创建 30 张业务表。该文档只提出登录安全所需的新增结构草案，未执行 DDL、未连接写入、未改变已批准的 30 表基线。

## 已知事实

- 新 API 已用服务器端签名会话替代 CloudBase 自动注入身份。
- 当前 30 张目标业务表中没有会话撤销、设备会话或 Token 版本账本。
- 仅依赖不可撤销的长期签名 Token，不能满足登出、设备丢失、管理员强制失效、密钥轮换后的精确失效要求。

## 推荐新增结构

建议在负责人确认后新增独立 `user_sessions` 表，而不把 Token、微信会话密钥或手机号原文塞入 `users` 表。

建议字段及约束：

| 字段 | 用途 | 约束 |
|---|---|---|
| `id` | 内部会话主键 | BIGINT 自增主键。 |
| `user_id` | 用户归属 | 外键或受控关联 `users.id`。 |
| `session_hash` | 服务端保存的会话标识摘要 | 唯一；禁止保存完整 Bearer Token。 |
| `token_version` | 用户级失效版本 | 与签名声明比对。 |
| `issued_at`、`expires_at`、`revoked_at` | 生命周期与撤销状态 | 分别建立用户/有效期索引。 |
| `last_seen_at` | 受限频率更新的活跃时间 | 不能作为每次读取都写库的理由。 |
| `created_at`、`updated_at` | 审计时间 | 统一 UTC/数据库时区策略。 |

不保存：微信 code、session_key、完整 Token、原始手机号、客户端 OpenID 参数、副本支付凭据。

对应的未执行迁移草案见 `server/migrations/001_user_sessions.sql`。它新增 1 张表，因此必须在负责人确认后先于隔离恢复库演练；当前目标库仍保持已批准的 30 表基线。

隔离演练脚本见 `server/scripts/rehearse-session-migration.sh`。该脚本只能在负责人明确批准后、以受控逻辑备份为输入运行；容器禁用网络、随机生成临时口令并在退出时清理。

## 实施协议

1. 负责人确认新增表与会话最长有效期后，先在隔离库执行受控迁移并跑会话签发、验证、撤销、过期、重复登出测试。
2. 通过后才在目标生产库增加该结构；生产变更单独记录 schema 版本、DDL 摘要与验证结果。
3. 将当前签名 Token 改为带随机会话标识和版本声明的短期访问凭据；每次鉴权校验有效会话摘要、撤销状态和版本。
4. 小程序切换前验证旧 CloudBase 登录态不会被误当作新会话。

## 当前影响

登录端点可在隔离环境验证身份交换与参数边界，但在会话账本未实施前，不得对公网、小程序或管理端开放真实登录流量。
