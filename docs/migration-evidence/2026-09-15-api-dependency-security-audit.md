# 2026-09-15 目标 API 依赖与配置安全审计

## 范围与方法

本次只读取本地 `server` 依赖锁文件和部署模板；未登录服务器、未变更 systemd、Nginx、防火墙、域名、证书或机密。

执行环境：Node.js `v24.19.0`、npm `11.17.0`。

## 结果

`npm audit --omit=dev --json` 报告：生产依赖 76 个、总依赖 77 个，已知漏洞为 0（信息、低、中、高、严重均为 0）。

当前仓库的 API systemd 模板具有以下安全边界：

- 服务以非 root 的 `deploy` 用户运行。
- API 进程仅监听 `127.0.0.1:3000`。
- 使用 `NoNewPrivileges`、能力清空、只读系统目录、受限设备/命名空间及 `UMask=0077`。
- 机密从受限环境文件读取，不写入仓库。

## 未放行项

`deploy/nginx/sravx-api-public.conf` 仍是候选模板，不能据此推断 API 已公开；它需要备案、证书、Nginx 实际配置、请求域名、限流配置和切换放行全部完成后才能启用。

`/readyz` 仅用于受控部署探针。公网启用候选模板前，需确认该路径的访问范围满足运维监控需要，且不向外泄露依赖状态细节。

## 后续

在每次实际部署前重新执行依赖审计、检查锁文件完整性，并在服务器上验证服务监听地址、systemd 沙箱状态和 Nginx 生效配置。该记录不能代替上线前复核。
