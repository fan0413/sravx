## 已知事实

当前管理端的认证与文件能力集中在 `src/lib/cloudbase.ts`：

| 能力 | 当前实现 | 新系统状态 |
|---|---|---|
| 管理员登录 | CloudBase 用户名密码认证 | 新 API 已有独立管理员会话接口；前端尚未接入 |
| 路由登录拦截 | CloudBase 登录状态 | 尚未替换 |
| 退出登录 | CloudBase `signOut` | 新 API 已有会话撤销接口；前端尚未接入 |
| 文件上传 | CloudBase `uploadFile` | 新 API 已有受控 COS 上传意图、预签名 PUT 与对象确认；前端尚未接入 |
| 临时图片访问 | CloudBase `getTempFileURL` | 新私有 COS 下载签名接口尚未实现 |
| 业务管理调用 | `callCloudFunction` | 商品、订单、优惠券、后台统计等等价新 API 未完整实现 |

`src/api/admin.ts` 与各业务页面继续调用 CloudBase 的 `admin-*`、商品、订单、优惠券、用户、剪刀、轮播、咨询和礼品卡等函数。管理端不能在当前阶段切到新 API；否则会出现“可登录但业务页面不可用”的半迁移状态。

## 推荐迁移顺序

1. 管理员登录、登出、路由守卫和 COS 上传适配；
2. 商品、分类、轮播的目录管理 API，配合“全部重新上传商品图片”流程；
3. 订单、库存、积分、优惠券、剪刀、礼品卡与咨询；
4. 最后处理支付和物流相关入口，并进行切换窗口演练。

## 放行限制

在目录 CRUD、管理员审计、私有 COS 下载签名及前端合同测试完成前，管理端制品必须继续保留 CloudBase 版本，不发布、不改 DNS、不切换访问流量。
