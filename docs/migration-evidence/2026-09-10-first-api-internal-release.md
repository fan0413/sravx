# 第一批 API 隔离内部发布证据

日期：2026-09-10。范围仅为服务器内部 API 骨架，不代表小程序、后台、支付或 CloudBase 已切换。

## 部署状态

- 服务：`sravx-api.service`，状态 `active` 且 `enabled`。
- 运行身份：`deploy`；监听范围：`127.0.0.1:3000`。
- Nginx、公网 API 路由、小程序、支付回调、DNS 与 CloudBase 均未改动。
- 外部 HTTPS `https://api.sravxpet.com/health` 在服务器侧验证仍返回 503；UFW 仅允许 22、80、443，API 端口 3000 仅绑定 `127.0.0.1`。
- MySQL API 服务账号以只读 `SELECT 1` 完成私网连通性验证。
- 2026-09-10 已补充 systemd 能力清空、设备/内核/控制组保护、命名空间与 SUID 限制、原生系统调用架构及 `UMask=0077`。内部健康检查通过，`systemd-analyze security` 暴露评分从 8.3 降至 3.7。

## 内部接口验证

- `/health` 返回固定健康状态。
- 商品、分类、轮播接口经目标 MySQL 只读查询返回空集。
- 空目录商品详情返回稳定的 `PRODUCT_NOT_FOUND`。
- 未登录管理端与用户资料接口均返回 401。
- 未调用真实微信登录，未创建用户或写入订单、支付、退款数据。
- 积分商品目录、分类、规格与默认会员等级的只读查询已内部验证为空集，未写入库存、积分或商品数据。

2026-09-10：已通过受控脚本对目标库采集只读基线。产物位于服务器受控迁移目录，权限为 `600`、所有者为 `deploy`；仅包含 30 张表的名称、精确行数和主键元数据。验证结果为全部 30 表均为 0 行，未读取业务行或写入目标库。

该基线仅证明当前空库状态。正式切换前仍须对冻结后的源与恢复后的目标运行完整逐表计数、分块哈希、关联完整性和业务对账。

同日已在同一目标空库完成分块哈希工具演练：30 张表均被识别，因全表为空而均无行块。产物同样只存受控迁移目录、权限为 `600`。该演练仅证明脚本可运行，不能作为源/目标业务数据一致性证据。
