# 后台剪刀编号库存接口实施记录（2026-09-17）

## 范围

本次仅在目标 API 实施新建商品的剪刀编号库存管理，未导入任何旧剪刀编号、商品、图片、绑定、积分、订单或售后数据。

接口位于 `/api/v1/admin/scissors`，需要目标后台账号具有 `catalog_editor` 角色：

- 查询目标商品与规格、编号清单和编号批次；
- 为目标库中已创建的商品生成新的未使用编号；
- 仅软删除未使用编号。

## 保护边界

- 新编号以加密随机数生成，数据库唯一约束仍是最终冲突防线；单次最多 500 条。
- 多规格商品必须明确选择规格；商品或规格不存在时拒绝创建。
- 编号详情固定返回 `binding: null` 与 `pointsLog: null`。本轮没有迁移用户绑定和积分奖励，也没有添加任何绑定、解绑、积分、订单、支付、退款或物流接口。
- 已删除的编号不出现在查询或批次汇总中。

## 验证

在 `server` 目录执行 `npm test`，结果为 77 项通过、0 项失败。新增覆盖确认：

- 后台剪刀接口要求目录编辑权限；
- 批量生成只把受控字段传入库存仓储；
- 详情不会返回绑定或积分迁移数据；
- 无权限管理员得到 403。

## 尚未切换

小程序仍未改为调用目标 API，后台前端也尚未将剪刀页面切换到新接口。待新商品在目标目录中建立、后台页面适配完成，并完成独立验收后再开放该业务入口。
