# 云函数迁移就绪性复核

日期：2026-09-17  
状态：未放行整体迁移；本文件只记录脱敏范围与条件，不含线上源码、配置值、个人信息或机密。

## 本次复核结论

- 已通过负责人可访问的 CloudBase MCP 重新核对线上函数清单：仍为 30 个活动函数，与 2026-09-10 的处置矩阵一致。
- 当前可以推进的是“空目录重建”所需的分类、轮播、商品后台与公开读取能力；它们不导入旧商品、媒体或库存。
- 已批准的数据范围只有 `users` 的基础身份和资料；商品、订单、地址、积分、优惠权益、礼品卡、剪刀、售后和历史咨询均不导出。
- 因此，**不能把“用户基础资料具备受控演练条件”扩大为“全部云函数可迁移”**。全部函数的 B-01/B-02 放行条件尚未满足。

## 共同阻断项

1. 当前线上函数的安全制品标识、配置名称、调用方和近期调用量尚未形成逐项可审计证据；不得把本地源码当作线上制品。
2. 目标服务端运行的 API 制品需与本地受测代码对应，并完成 schema、健康检查、权限和回归验证后，才可承接目录功能。
3. 生产数据库完整 DDL、全表快照、对象清单、订单/支付例外与回调队列仍未按迁移计划完成受控演练；当前禁止进入全量数据切换。
4. 小程序仍未切换到新 API；即使 API 域名已配置，也必须在目标数据、认证和兼容回归通过后才可打开迁移开关或发布版本。

## 下一步执行顺序

1. 在隔离环境完成 `users` 基础资料的源/目标结构预检和一次性导入演练，只保存私有快照与脱敏摘要。
2. 将目录管理模块以目标 schema、RBAC、COS 上传和空目录回归作为一个独立发布批次验证；不导入旧商品和图片。
3. 为 30 个线上函数补齐逐项调用方、处置责任人和安全制品证据，先关闭低代码/遗留入口的归属缺口。
4. 在支付、订单、物流和个人信息规则明确后，分别做专项实现与演练；其完成前不进入最终停写或 CloudBase 退役。
