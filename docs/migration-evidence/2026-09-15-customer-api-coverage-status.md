# 客户端 API 覆盖状态（2026-09-15）

## 结论

以 `miniprogram/utils/api.js` 的调用点和 `server/src/server.js` 的路由为准，当前兼容 API 已覆盖商品/分类/轮播读取、用户资料与积分读取、地址簿、工具档案绑定、工具售后、普通订单与积分订单读取、礼品卡兑换记录读取，以及部分用户资料写入。

下列能力仍由 CloudBase 函数处理，不能在未完成事务、幂等、鉴权和回调演练前迁移为生产写入：

| 业务域 | 未迁移动作 | 风险与后续条件 |
|---|---|---|
| 普通订单 | 创建、取消、确认收货、物流令牌、退款申请与退款记录 | 库存、优惠券、支付、售后状态必须形成完整事务与幂等链路。 |
| 积分订单 | 创建、取消、退款申请与退款 | 涉及积分扣减/返还及库存，需账本和并发测试。 |
| 微信支付 | 创建支付、退款 | 必须先完成回调验签、独立入站存储、重放与对账演练。 |
| 优惠券 | 可用券、我的券、领取、校验 | 领取和核销需要唯一约束、用户归属和订单事务。 |
| 礼品卡 | 兑换、商品礼品地址确认 | 兑换码和记录须在单事务内幂等处理；现有只读接口需先完成完整性核验。 |
| 工具档案 | 保修查询、解绑 | 保修状态和绑定历史需先明确数据规则，避免错误释放已绑定 SN。 |
| 合作咨询 | 提交咨询 | 涉及个人信息；先落实字段最小化、保留期、频率限制和访问控制。 |

## 部署边界

小程序的 `authenticatedApiMigration` 与 `readOnlyApiMigration` 开关默认关闭，因此上述本地兼容层不会改变当前线上用户请求路径。服务器当前仍为 9 月 11 日隔离制品，本文件不构成部署或切换授权。

## 建议顺序

1. 先完成礼品卡完整性核验的受控演练，决定是否可以继续礼品卡写入迁移。
2. 建设支付回调入站、验签、幂等与回放能力，再处理普通订单和积分订单写入。
3. 最后处理优惠券、物流与合作咨询，并以小程序开关做隔离验证。
