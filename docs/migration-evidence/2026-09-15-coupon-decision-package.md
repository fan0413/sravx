# 优惠券迁移决策包

日期：2026-09-15  
状态：等待业务负责人决策；本文件不授权任何生产数据或规则变更。

## 已知事实

- 旧 `coupon` 云函数提供模板列表、我的优惠券、领取与可用性检查；`receive` 当前由“查询可领券 → 查询是否已领 → 插入用户券 → 扣减余量”四步组成，未形成明确的单事务边界。
- 每次调用旧函数都会尝试补写缺失的券码。这类运行期写入不应原样迁入新服务。
- 新商品目录、型号、颜色与 SRAVX Protect 的报价快照仍在迁移准备中。现有优惠券规则未确认是否能作用于新 SKU、定制服务或 Protect。
- 迁移计划和函数处置矩阵均要求：旧券不得在新目录中被误用；领取与核销需要唯一约束和事务。

## 建议决策

推荐：**旧券归档，新目录启用重新创建的优惠券活动。**

理由：新目录的 SKU、价格、服务项和结算报价将由服务端确定；重新创建能明确适用商品、是否可叠加 Protect、门槛、有效期和预算，避免旧规则造成错误折扣或订单金额不一致。

可选方案如下，需从中明确一项：

1. **归档并重建（推荐）**：旧券只保留历史查询与对账；新目录仅接受新券。
2. **限期兑现旧券**：保留指定历史券，并逐券配置有效期、适用 SKU、是否适用于 Protect 与定制服务、不可叠加规则及预算上限。
3. **人工转换**：筛选符合条件的未使用旧券，按人工确认的映射转换为新券；原券状态保留转换审计记录。

## 新接口进入实现前的准入条件

- 明确上述方案及所有例外券范围，形成负责人确认记录。
- 定义券模板字段：面额/折扣、最低消费、适用 SKU 或系列、适用服务项、可叠加规则、发放上限、每用户上限、开始与结束时间、状态与条款版本。
- 定义订单报价规则：服务端报价单确认优惠金额；创建订单时在同一事务中锁定券、校验可用性、扣减余量、写入使用记录、保留订单折扣快照。
- 数据库层提供 `user_id + coupon_id` 唯一约束、领券幂等键、使用记录唯一关联和库存/余量条件更新；不得依赖客户端金额或前端校验。
- 完成并留存并发领券、重复提交、取消订单释放、支付超时、订单退款、历史券查询和对账的演练证据。

## 当前处理

- 小程序继续沿用旧优惠券链路；新 API 不暴露优惠券领取、核销或订单折扣写入口。
- 不执行旧券禁用、迁移、复制或删除，也不修改任何生产优惠券数据。
- 在负责人决策前，订单、支付、积分和礼品卡写链路继续保持在原系统，避免长期双写。
