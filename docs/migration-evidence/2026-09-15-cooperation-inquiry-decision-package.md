# 合作咨询迁移决策包

日期：2026-09-15  
状态：等待业务负责人决策；本文件不授权收集、复制或导出任何生产个人信息。

## 已知事实

- 旧 `contact` 云函数接收合作咨询表单，并保存姓名、联系电话、微信号、所在地、经营规模、意向和提交时间。
- 该信息属于个人信息；旧函数仅做长度截断，未体现提交频率控制、用途告知、保存期限或删除机制。
- 当前小程序仍调用旧函数；新服务没有对应写接口，因此不会向目标数据库新增咨询数据。

## 新接口最低设计

- `POST /api/v1/cooperation-inquiries` 仅接收完成咨询所必需的字段；服务端从已验证会话取得用户身份，不接受客户端传入用户标识。
- 对字段类型、长度和枚举值做服务端校验；日志中只记录请求追踪标识和结果，不记录联系电话、微信号、地址或咨询正文。
- 以用户身份、设备/网络信号和时间窗口做限频；重复提交返回幂等结果，避免重复线索。
- 查询、导出、分配和状态变更仅向具备明确角色的管理端人员开放，并写入审计记录。
- 数据到期后按确认的规则删除或匿名化；备份与恢复流程沿用相同期限。

## 需负责人明确的规则

1. 收集目的和向用户展示的隐私说明链接。
2. 每个字段是否为必填，以及是否确有业务必要性；建议默认不收集详细地址与微信号。
3. 保存期限、到期后的删除或匿名化方式，以及是否允许人工延长。
4. 咨询线索的处理角色、导出权限和审计保留期限。
5. 提交频率和重复咨询的业务处置规则。

## 当前处理

- 旧咨询功能保持过渡运行；新 API 与管理端均不读取或写入该类数据。
- 未确定上述规则前，不复制历史咨询记录，也不建立目标库同步或双写。
- 规则确认后，再补充接口合同、权限测试、限频测试、删除演练和负责人验收证据。
