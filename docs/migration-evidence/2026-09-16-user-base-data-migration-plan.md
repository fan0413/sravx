# 用户基础资料迁移计划（2026-09-16）

## 负责人已确认的范围

本批仅迁移源 `users` 表的用户身份、账户状态和基础资料，并在目标库生成 `user_identities` 绑定。所有商品目录均不导出，任何订单均不导出。

本批不迁移地址、积分/会员累计字段、优惠券、礼品卡、剪刀、售后、会话、头像字段或媒体文件。地址等个人资料需要独立的最小化评估和确认后才可另行处理。

## 执行前检查

1. 受控私有迁移位置可用，并仅向执行人员和目标服务账号授予最小权限。
2. 从同一冻结时点导出完整源 DDL及 `users` 的最小字段快照；完整 DDL只用于结构核验，不放入版本库。
3. 在隔离目标库核验 `users` 的字段、主键、状态枚举和唯一约束，随后执行目标 `user_identities` 草案迁移的隔离演练。
4. 用只含汇总数的报告检查：源用户数、成功导入数、OpenID/UnionID 绑定数、空值数和冲突数。身份冲突不自动合并，转人工处理。

仓库中的 `server/scripts/user-import-preflight.mjs` 用于该阶段：它分别以只读连接检查源、目标 `users` 结构与目标 `user_identities` 唯一索引，只在受控输出位置写入列名、结构与汇总数，不读取或输出用户明细。

`server/scripts/user-basic-snapshot.mjs` 仅导出获准字段，并使用一致性只读快照写入权限为 600 的受控文件；`server/scripts/import-user-basic-snapshot.mjs` 必须显式携带 `--apply`，且要求目标 `users` 为空，才会在一个事务中写入用户与身份绑定。

## 迁移规则

- 保留用户主键，避免后续已关联历史数据时产生不可追溯的 ID 重写。
- 只复制身份识别、账户状态和基础资料所需字段；积分、累计消费、订单数量和会员等级保持目标默认值，等待账本/订单迁移方案。
- 不复制旧会话、登录令牌或任何第三方凭据；目标会话仅由目标登录服务签发。
- 目标身份表以 `(provider, provider_subject)` 为唯一键。OpenID 与 UnionID 缺失或冲突的记录不进入自动导入结果。

## 验收与回退

目标库的用户汇总数与冻结快照一致，身份绑定没有重复，且内部测试账号可被目标登录流程识别为原账户。小程序认证迁移开关保持关闭，直到单独完成登录、资料与地址簿的隔离测试。

导入失败时停止目标侧处理并保留受控审计证据；不修改源 CloudBase 数据，不删除用户数据，也不发布小程序版本。
