# 首批目录数据迁移执行计划（2026-09-16）

## 目的与边界

本批只为小程序“只读目录”迁移准备数据：分类、商品、商品规格、首页轮播图，以及这些记录引用的媒体对象清单。它不包含用户、地址、订单、库存扣减、积分、礼品卡、支付、退款或售后数据，也不改变 CloudBase 线上写入路径。

2026-09-15 的只读基线显示源库中有 `categories` 15 条、`products` 11 条、`product_specs` 23 条、`banners` 5 条。本计划不把该基线当作可直接导入的数据文件；执行时须再次以冻结快照为准。

## 当前状态

- `https://api.sravxpet.com/api/v1/catalog/home` 已可访问，但目标目录返回空集合。
- 小程序已登记 request 合法域名，迁移开关保持关闭，用户仍从 CloudBase 读取目录。
- 本地版本库没有完整源库 DDL；局部 SQL 不能重建完整业务表结构，详见 `2026-09-15-schema-source-coverage-gap.md`。
- 目标 API 约定媒体为受控 COS object key（例如 `catalog/products/`、`catalog/categories/`、`catalog/banners/`）；源记录中的媒体引用格式和源对象清单尚未核验，不能直接猜测或改写。

## 获准后的一次性操作顺序

1. 将源 MySQL 的完整 DDL 与本批四张表的同一时点只读数据快照导出至受控私有迁移位置；同时生成被引用媒体的对象键清单和校验信息。导出物不得提交 Git、放入普通工作目录或粘贴到聊天中。
2. 在隔离目标库按完整 DDL 恢复，并在恢复成功后叠加已编号的目标服务补充迁移；对源、目标运行 schema diff，记录每一项差异及批准理由。
3. 先导入分类，再导入商品、规格和轮播图；保留源主键及关联关系，或在转换表中显式记录新的映射，禁止靠名称匹配关联。
4. 将清单中实际被引用的媒体复制到私有 COS 的受控前缀，并生成“源引用 → 目标 object key”的映射；确认每个已迁移对象可被服务端签名读取。未经核验的媒体不得写入目标目录记录。
5. 在目标 API 做只读验证：首页、分类列表、商品列表、商品详情、规格、轮播图和图片回显均与冻结快照一致。验证通过前，不开启小程序 `readOnlyApiMigration`。

## 放行校验

- 四张表的行数与冻结快照一致；每个 `products.category_id` 都能关联到目标分类，每个 `product_specs.product_id` 都能关联到目标商品。
- 已展示的商品、分类、轮播图不存在缺失、越权或未映射的媒体引用。
- API 返回的目录接口不再为空，分页、详情和规格顺序符合快照。
- 管理端读取同一目标库时能回显相同目录数据；不以管理端手工重建数据替代迁移。
- 使用内部测试账号和真机验证只读目录后，才能单独评审是否开启小程序只读开关。

## 回退与限制

执行和验证期间小程序继续使用 CloudBase 目录，目标库不承接用户业务写入；验证失败只关闭候选读取路径并保留证据，不删除源数据、不退役 CloudBase。订单、支付、退款、库存及其他业务写入仍留在后续独立迁移批次。

## 需要负责人确认

从 CloudBase 生产 MySQL 导出完整 DDL、首批目录数据快照及其关联媒体清单，并将数据复制到受控迁移位置，属于生产数据/文件复制。获得明确确认前，本计划只作为准备记录，不执行导出、复制、导入或开关切换。
