## 6. 关键限制与风险

1. **不能把“接口可用”视为“支付已验收”。** 当前还没有一笔新普通订单的真实小额支付、回调入账和订单状态结算证据。
2. **支付入站与业务库共用数据库。** 数据库不可用时，回调持久化与订单结算会同时受影响；这是当前单库方案的主要风险。
3. **支付消费者需要补强宕机恢复。** 现有消费者具备交易唯一键结算，但须增加“处理状态超时回收/安全重放”的集成演练，避免进程在领取事件后中断造成事件长期停留在处理中。
4. **积分混合支付和真实退款尚未受控演练。** 代码与自动测试已具备，但在真实付款、真实退款、回调重放和异常恢复获得证据前，不应向用户开放。
5. **商品目录为空。** 在管理端创建商品、库存和图片前，无法做真实商品订单验收。
6. **CloudBase 退役条件未满足。** 低代码、物流、旧支付、旧客户端覆盖和历史售后仍未完成核验。
