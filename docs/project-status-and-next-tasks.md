## 2. 已确认的业务边界

1. 品牌面向中国宠物美容师，产品为中高端宠物美容剪刀及相关用品。
2. 旧商品、分类、图片、订单、地址、积分、优惠券、礼品卡、剪刀、售后、咨询和媒体不导入目标库；新系统中的商品与权益均作为新业务重新建立。

4. CloudBase 仍作为旧系统与历史参考保留，尚未获准删除、停用或退役。
5. 支付回调账本与业务库继续共用同一 MySQL 数据库，这是负责人已确认的部署选择；因此两者共享同一故障域，需要加强监控和演练。

## 6. 关键限制与风险

1. **不能把“接口可用”视为“支付已验收”。** 当前还没有一笔新普通订单的真实小额支付、回调入账和订单状态结算证据。
2. **支付入站与业务库共用数据库。** 数据库不可用时，回调持久化与订单结算会同时受影响；这是当前单库方案的主要风险。
3. **支付消费者需要补强宕机恢复。** 现有消费者具备交易唯一键结算，但须增加“处理状态超时回收/安全重放”的集成演练，避免进程在领取事件后中断造成事件长期停留在处理中。
4. **积分混合支付和真实退款尚未受控演练。** 代码与自动测试已具备，但在真实付款、真实退款、回调重放和异常恢复获得证据前，不应向用户开放。
5. **商品目录为空。** 在管理端创建商品、库存和图片前，无法做真实商品订单验收。
6. **CloudBase 退役条件未满足。** 低代码、物流、旧支付、旧客户端覆盖和历史售后仍未完成核验。

  - 前置条件：所有旧回调、退款、物流、售后和旧客户端依赖已结束，且负责人明确批准删除或停用。

## 8. 维护规则

1. 每次部署后更新“当前运行状态”和对应任务的验收证据。
2. 每次真实支付、退款、发布或外部平台配置变更，都在本文件和迁移执行证据中记录时间、范围、结果和回退方式，但不记录订单号、用户信息、回调原文或机密。
3. 任务完成必须附验证结果；仅完成编码或构建时标为“代码完成，待验收”。
4. 发生新的业务决策时，先更新第 2 节，再安排实现任务，避免文档与实际范围冲突。
