# 小程序前端近期改动：管理端适配清单

更新：2026-09-14。本文用于后续管理端开发排期，不实施数据库迁移、商品发布、SN 批量生成或生产数据修改。

## 结论

小程序已从“按剪刀形态直接浏览”调整为“先选系列、再选用途与形态”的产品体验。后续管理端应优先补齐结构化的商品系列、工具形态和媒体用途字段；不要继续依赖商品名称中的 `Basic`、`Pro`、`Master` 文字判断归属。

剪刀绑定成功后的欢迎动效和工具档案跳转已在小程序完成。管理端后续应提供受审计的 SN 入库与状态查询能力，但不应提供绕过用户绑定流程的“替用户绑定”入口。

## 已上线的小程序体验

| 模块 | 当前体验 | 对管理端的影响 |
|---|---|---|
| 首页产品入口 | 横滑展示 Basic、Pro、Master、配件四个系列；点击进入对应系列目录。 | 商品必须有可维护的系列归属与系列展示排序。 |
| 商城目录 | 系列 → 用途（直剪、弯剪、造型剪、套装与配件等）→ 二级形态（如小弯剪、大弯剪）。 | 商品需要用途组和二级形态，分类页需避免把系列与形态混成同一级。 |
| 商品详情 | 圆角主视觉、独立名称/说明/售价、设置页式规格与参数、长图产品故事区。 | 商品编辑需明确主图、轮播图、详情长图、剪刀档案卡图的用途。 |
| 购物袋 | 底部第二项为购物袋；当前按单件进入既有确认订单流程。 | 商品上下架、规格、价格与库存仍需保持现有合同；不要求后台实现多商品合并订单。 |
| 我的剪刀 | 列表仅显示图片与名称，点击后查看型号、SN、激活日期、保修期和售后。 | 后台应维护 SN 与商品/规格的准确关联，确保档案页展示准确。 |
| 绑定反馈 | 成功后显示 “The Tools You Deserve.”，用户点击“查看工具档案”进入刚绑定工具的档案页。 | 文案目前固定在小程序，不需要后台配置项。 |

## 已知事实

1. 当前新后台商品输入已支持商品名称、简介、价格、分类、主图、轮播图、详情图、剪刀档案卡图、参数、保修期、规格、库存和履约字段。
2. 当前新后台商品输入和 `products` 写入合同中没有结构化 `series`、`tool_group`、`tool_subtype` 字段。
3. 当前小程序系列筛选为兼容已有目录，暂从名称、描述和可能存在的系列字段中识别 Basic、Pro、Master；配件则依据配件、套装、收纳、养护、保养、服务等文字或分类识别。
4. 当前剪刀绑定依赖 `scissors` 与 `user_scissors`；SN 绑定完成后会建立用户绑定记录并更新工具状态。管理端 RBAC 合同明确 `admin-scissors` 尚未进入首批实现。

## 建议的商品目录模型

### 1. 系列：一级入口

使用枚举字段 `series`，不允许自由输入：

| 值 | 管理端显示 | 材质定位 | 小程序文案 |
|---|---|---|---|
| `basic` | Basic | 9Cr | 入门专业款 |
| `pro` | Pro | 440C | 专业主力款 |
| `master` | Master | VG10 | 高阶专业款 |
| `accessories` | 配件 | 收纳与养护 | 专业工作配套 |

`series` 是产品目录定位，不等同于商品分类。材质以系列默认值展示；若具体商品存在例外，应另设真实材质字段，不能借系列名称虚构材质。

### 2. 用途与形态：二、三级筛选

建议字段：

| 字段 | 示例 | 用途 |
|---|---|---|
| `tool_group` | `straight`、`curved`、`texturizing`、`accessories`、`other` | 商城第二层用途筛选。 |
| `tool_subtype` | `small_curved`、`large_curved`、`thinning`、`fishbone` | 同一用途下的具体形态。 |
| `display_size` | `6.5`、`7.0`、`7.5` | 尺寸筛选与商品参数展示。 |
| `steel_material` | `9Cr`、`440C`、`VG10` | 商品真实材质；仅在有真实数据时填写。 |

尺寸、材质和形态均应成为可验证的结构化数据。商品标题可以保留营销表达，但不能承担目录筛选职责。

### 3. 媒体字段与上传要求

| 媒体用途 | 管理端字段/现有能力 | 建议素材规格 | 小程序位置 |
|---|---|---|---|
| 商品主图 | `cover_image` | 白底或克制背景，建议正方形，主体居中 | 商品详情主视觉、系列卡回退图。 |
| 商品轮播 | `images` | 同一产品视觉体系，建议正方形或接近正方形 | 商品详情轮播。 |
| 产品故事长图 | `detail_images` | 宽 750rpx 适配的竖向长图；文字留足边距 | 商品详情“产品故事”。 |
| 工具档案卡图 | `scissors_card_image`，可由规格卡图覆盖 | 3:2 横向，完整包含剪刀、包装与吊牌 | 我的剪刀列表与档案。 |
| 规格图/卡图 | 规格的 `image`、`card_image` | 对应具体 SKU，不混用其他规格图片 | 规格选择和 SN 工具档案。 |

上传后先预览再发布。旧 `cloud://` 媒体不迁入新 COS；后续重新上传商品时由后台写入新的受控对象键。

## 管理端页面与接口待办

### P0：商品编辑与目录发布

1. 在商品编辑表单增加：系列、用途组、二级形态、尺寸、真实材质、首页/系列排序。
2. 在列表中增加系列、用途、是否上架、主图完整性筛选；支持按系列预览小程序目录。
3. 发布校验：非配件商品必须有系列、用途、主图、至少一个价格/规格和保修期；配件按实际业务规则放宽尺寸要求。
4. 商品详情媒体区按用途分栏，不以“图片数组”混合管理主图、轮播、长图与工具档案卡图。

### P1：SN 与工具档案管理

1. 建立受权限控制的“SN 批次入库”页面：SN、批次、关联商品、关联规格、型号、生产日期、积分值、初始状态。
2. 支持按 SN、批次、商品、规格、状态查询；状态至少区分 `unused`、`bound`、`sold`、`expired`。
3. 提供只读绑定历史、保修状态和售后关联摘要；敏感个人信息按 RBAC 脱敏展示。
4. SN 创建、导入、更正、状态调整均需审计记录、幂等键与重复 SN 校验。不得在前端或普通导出中暴露完整用户信息。

### P2：运营预览与内容一致性

1. 增加小程序商品详情预览，检查主图裁切、文字长度、参数缺失和详情长图顺序。
2. 增加系列目录预览，检查 Basic/Pro/Master/配件四个入口的图片、数量、排序和空态。
3. 欢迎层文案暂固定为 `The Tools You Deserve.`；如未来开放配置，限制为经审核的品牌文案，不能由运营随意插入外链或脚本。

## 不应纳入本次管理端适配

- 不新增“替用户绑定/解绑剪刀”按钮；用户绑定仍由小程序 SN 验证流程完成。
- 不将支付、退款、积分或库存做成可绕过审计的直接修改入口。
- 不把完整 SN、收货信息、订单信息或访问密钥导出到普通表格、Git 或运营文档。
- 不为兼容旧页面继续以商品标题关键词作为长期目录数据源。

## 验收清单

- 新建 Basic、Pro、Master、配件各一件测试商品后，首页与商城均能进入正确系列。
- 同一系列商品可按用途、二级形态和尺寸筛选，不依赖名称匹配。
- 主图、轮播、详情长图、工具档案卡图在各自页面不发生错误复用。
- 新建未绑定 SN 可完成小程序绑定；欢迎层只在用户点击后进入对应档案页。
- 管理端无权限角色不能新建或修改 SN，任何 SN 写操作可在审计中追溯。

## 实施顺序

1. 先完成 P0 的结构化字段与发布校验，再将小程序从关键词兼容切换为字段筛选。
2. 再完成 P1 的 SN 管理与审计，并做绑定、保修、售后回归测试。
3. 最后补 P2 的预览和运营体验。

任何生产数据库结构变更、商品发布、SN 批量导入或权限调整，仍需按迁移计划和 RBAC 合同单独确认后实施。
