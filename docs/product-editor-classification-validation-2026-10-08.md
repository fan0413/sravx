# 商品编辑：系列与细分类本地验收

日期：2026-10-08。仅在 E:\sravxapp 开发；负责人暂停上传和上线。本次未提交、推送、部署、写生产商品、修改数据库结构或打开交易迁移开关。

## 检查发现与修正

- 普通编辑只有平铺 category_id，且默认第一项。现增加 Basic / Pro / Master / 配件选择；剪刀系列再选直剪、弯剪、牙剪、鱼骨剪、造型剪，再关联对应目录分类。系列切换清除旧剪型与关联分类，新建不自动选择第一项。
- 分类管理补充顶级系列父级选择、level 传递；筛选结果与完整父级选项分开。后端拒绝自身、无效父级、三级分类；有子分类的系列不能删除。不会自动创建或改写线上分类。
- 分类信息存入现有 params JSON 的“目录系列”“目录分类”，普通商品创建/更新可持久化，无须启用结构化 SKU/支付开关或增加数据库列。剪刀枚举与配件组合有后端输入校验；网页、小程序共同使用同一分类解释函数，优先明确保存值，兼容历史 series 字段、分类父级和名称识别。
- 原 SKU 页面系列/用途改为只读，读取普通编辑的数据，避免第二个手填入口；结构化 SKU 接口仍受原开关保护。
- 编辑保留额外参数、展示卡片对象引用及原排序。修正同组件从编辑切到新建残留数据。详情图限制 30 张，与目标 API 一致。
- 两端目录参数适配将 params 中技术字段映射为前端显示字段；列表与购买解析补充分页，不再只取分类前 20 件或前 100 件。请求失败继续报错，不吞成空分类。
- 普通现货可不填延迟原因/补充说明；特殊延迟仍要求原因，发货承诺与天数仍校验。配件暂不强制填写剪刀五项参数；不预设配件细分类。
- 本地旧 cloudfunctions/admin-product 只写固定技术字段，不保存扩展 params，无法证明旧运行函数已适配。因此旧保存模式明确阻止新分类信息提交，不静默丢字段，也不自动切换环境。旧小程序目录读回退保留；运行中的云函数状态未核查。
