# 小程序确认订单、地址与支付来源修复

日期：2026-10-09。负责人在明确布局、地址、普通支付接口及仅本地构建范围后确认“修复”。

## 根因与变更

- 确认订单页有自定义nav，而pages.json仍启用原生导航，截图出现双标题及空白。改为custom导航并修正nav/scroll盒模型，商品文本容器允许收缩，保留底部安全区。
- 地址保存截图显示旧云函数环境不存在。现有API按构建开关路由；默认构建未开启地址迁移。新增独立支付测试构建，启用现有服务器会话、地址、订单及支付，不猜测旧CloudBase环境，不擅自删除其他兼容能力。
- 普通确认订单原未传backend，导致服务器订单误入旧支付函数。订单创建统一附带实际来源标记并传给支付；目标支付开关未开时直接拒绝，不能自动回退旧事实库。
- 地址编辑增加并发保存保护、手机号格式检查、安全短错误提示；选址模式保存后写入对应选择缓存并返回，包含订单和礼品卡等已有入口。

## 验证

- `node --test scripts/*.test.mjs`：36项通过，包含新地址HTTP CRUD、普通订单支付路由、旧订单兼容、服务器支付关闭不回退、选址保存返回与防重复、单一导航配置。
- `npm run build:mp-weixin:payment-test`编译成功，26页面、无分包；独立产物核验脚本通过，实际bundle服务器profile/addresses/orders/payments开关为true，导航JSON为custom，确认订单包含实际来源标记。
- `git diff --check`无格式错误，仅已有CRLF提示。保持用户既存改动，D盘未修改。
- 小程序技能要求保留发布边界及付款安全，本轮仅修复并本地构建；代码审查确认未新增密钥、未经授权的数据接口或跨库支付回退。
