# 页面返回入口补齐

日期：2026-10-09，E盘主工作区。负责人确认修复前次检查发现的缺失返回入口与空历史栈问题。

## 实现

- 共用navigation模块定义23个非入口页面上级，并统一历史优先与失败/空栈回上级。无需读浏览器外部历史，不把返回上级固定为欢迎页或产品展示页。
- 共用返回组件沿用品牌黑白、既有字体与左侧点击布局。购物袋与个人中心嵌入既有导航栏，目录页面留出状态栏/胶囊安全区；16个原生导航页面仅在单页直接入口时补充返回动作，正常堆栈时沿用原生返回。
- 订单列表、商品详情、确认订单与选购页现有返回动作使用共用回退机制。H5登录保留既有返回官网，不重复显示补充按钮；首页/欢迎/启动页不添加返回。
- 不改变页面层级、底部导航业务行为、商品信息、支付调用、数据库及生产配置。

## 核验与限制

- 80项前端隔离回归通过，包括全页面上级映射、历史返回、无历史、返回失败、订单详情参数、直接入口可见性及原生导航不重复。
- 默认微信构建26页通过；产物核验23个非入口页面返回控件，原生导航配置仍保留；既有服务器接口来源检查通过。
- H5构建通过。产物检查最初误用模板方法名作为断言，而编译器会把名称转换为字母绑定；现改为核验编译JS的安全返回函数及模板点击绑定，完整默认构建复验通过。
- 初次采用UniApp easycom自动解析，CLI产物核对通过；后续发现HBuilderX目录页dev产物usingComponents为空。因此19个引用组件的页面已改为显式导入与注册，追加源码回归约束；不能以CLI结果替代HBuilderX实际完整编译验收。详见 `address-collation-and-hbuilder-navigation-fix-2026-10-09.md`。
- 无微信真机或开发工具模拟器点击验收；未发布、未订单/支付/地址写入。负责人需从E盘源码重新编译，重点核对购物袋、我的、产品目录及直接打开详情的返回与安全区。
