# 第一批 API 隔离发布检查卡

更新：2026-09-10。此检查卡仅适用于当前本地 API 骨架的内部发布验证。它不授权小程序切流、支付迁移、数据导入、生产交易或 CloudBase 退役。

## 待发布内容

- 小程序身份交换、短期服务端会话、目标库用户解析与空目录读取接口。
- 监听 `127.0.0.1:3000`，由既有 Nginx 的 HTTPS 站点代理 `/health` 和 `/api/v1/`。
- 不包含支付、退款、物流、订单写入、COS 上传、后台写入或小程序代码替换。

## 已执行的隔离内部发布

2026-09-10：API 代码已部署到服务器 `/opt/sravx-api`，以 `deploy` 用户运行的 `sravx-api.service` 已启用。服务仅监听 `127.0.0.1:3000`，尚未配置 Nginx 反向代理或公网 API 路由。

已完成的内部验证：

1. `/health` 返回固定健康状态。
2. 空商品目录接口返回空数组，符合新目录尚未上传的状态。
3. 未携带会话的管理接口返回 401。
4. 未调用微信登录端点，未创建用户，未写入订单、支付或退款数据。
5. `GET /api/v1/me` 在无会话时返回 401；未通过真实登录访问用户资料。
6. 商品、分类和首页轮播接口已改为目标 MySQL 的绑定参数只读查询；当前均返回空集，未写入目录表。

## 数据校验工具准备

- `server/scripts/row-baseline.mjs` 已提供只读逐表行数、主键定义和单列主键范围采集，产物须写入受控目录并以 `600` 权限创建。
- 该工具不导出业务行或机密，也不生成分块行哈希；最终切换仍需按迁移计划第 14 节补充分块哈希和业务对账，不能以此简化验收。
- `server/scripts/row-chunks.mjs` 已准备冻结窗口专用分块 SHA-256 校验：按固定列顺序与主键排序，显式编码 NULL、空串、二进制和规范化 JSON。它使用 OFFSET 分块，因此只能在已验证无写入的冻结快照上运行。

启动过程中发现并修复了两项部署问题：服务写目录未创建，以及启动入口与运行时模块形成循环加载。修复后服务稳定运行；Nginx 和 CloudBase 均未改动。

## 发布后允许的验证

1. `curl http://127.0.0.1:3000/health` 返回固定健康状态。
2. 通过 Nginx 仅验证 `/health` 的 HTTPS 反向代理。
3. 验证未授权管理接口返回 401，空目录接口返回空集。
4. 不调用真实微信登录、不创建用户、不写订单、不做支付或退款。

## 不通过处理

- Nginx、服务启动、机密权限或 MySQL连通性任一失败：保持现有维护页，停止新服务，不修改 CloudBase。
- 一旦任何生产用户数据写入目标库：遵循迁移计划第 13 和第 15 节的单一事实库与前向修复协议，禁止直接切回旧库。
