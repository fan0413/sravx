# 项目记录

## 要做什么

商品需要展示规格、剪型和图片，后台负责维护这些信息。官网和小程序都读同一份数据，后面改商品时不用分别处理两个端。

先把目前的功能关系和遇到的问题记在这里，后面改动时方便查。

## 功能分工

1. 官网入口展示剪刀，可以拖动、切换和暂停；进入官网后看系列及商品详情。
2. 小程序处理用户资料、地址、订单和售后等页面。
3. 管理端维护商品、规格价格、图片和分类，处理订单及售后。
4. 用户端请求集中在api.js，后台请求集中在admin.ts，参数查接口备忘。

日常调试用模拟数据。涉及登录、下单、退款和物流时，要区分本地测试与线上操作。

## 已处理的问题

| 问题 | 处理方法 |
|---|---|
| 两个客户端分类不一致 | 共用分类和价格处理函数 |
| 页面刷新后才更新 | 检查路由参数和页面刷新逻辑 |
| 图片临时地址过期 | 重新查询商品，不把签名地址存回数据库 |
| 已过期云环境仍被调用 | 把用户端请求集中改到服务器接口 |
| 拖动后误点到图片 | 区分点击和拖动，松开后再切换 |
| 页面构建成功但上线不一定正确 | 检查服务器文件、HTTPS和实际浏览器页面 |

## 待处理

网页登录和完整网页支付需要继续验收；小程序也需要更多真机检查。管理端有较大的打包文件，后面可以再拆分。测试命令目前主要手动执行，还没有完整自动发布流程。

性能和覆盖率还没做系统测量，先不记录估算数字。每次改动先跑对应模块测试，再确认页面实际效果。
