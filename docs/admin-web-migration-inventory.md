# 管理端迁移盘点

## 线上静态托管实时核验（2026-09-10）

CloudBase MCP 只读核验确认静态托管服务处于在线状态，使用 CloudBase 内置静态桶而非外部存储；站点首页为 `index.html`，自动寻址已启用。完整分页枚举得到 617 个对象、14,318,827 字节。

该数量明显高于本地一次受控生产构建的 49 个文件，说明线上桶保留了多次发布的旧制品和平台认证相关制品。不能从对象数量推断某一版本是当前后台，也不得据此删除、覆盖或复制文件。CloudBase 的 `__auth/` 制品不能作为新后台认证实现迁移；新后台须使用独立登录、RBAC 和新的发布制品。

## 旧认证依赖实时核验（2026-09-10）

CloudBase MCP 只读查询显示，当前环境启用用户名密码与匿名登录，未启用邮箱或手机号登录，并配置了 4 个认证提供方。该结果说明旧后台的 CloudBase 用户名密码会话不能作为新后台身份体系直接迁移。新后台必须另行实现管理员账号生命周期、角色权限、会话失效和审计；认证提供方的机密配置和值不进入迁移文档或新服务代码仓库。

更新：2026-09-10。此为本地源码盘点，不是发布或上线记录。

## 已知事实

- 管理端 Vue/Vite 源码位于 `E:\image\admin-web`，共 32 个 `src` 文件。
- 构建命令为 `vue-tsc -b && vite build`；生产环境仅定义 `VITE_API_BASE_URL` 这一前端环境变量名。
- 当前源码在登录、路由、管理 API 和图片上传处直接依赖 CloudBase：用户名密码登录、`callFunction`、`uploadFile` 和临时文件 URL。
- 商品编辑、积分商品编辑和轮播编辑均处理历史 `cloud://` 文件 ID；该模型不能直接用于目标 COS。
- 2026-09-10 已在受控本地目录完成生产构建验证：生成 49 个文件、约 2.26 MB，入口文件存在。构建产物未发布。当前 CloudBase SDK 形成约 1.58 MB 的单独前端代码块，移除浏览器直连 CloudBase 是后续体积与安全改造项。

## 改造目标

1. 登录改为目标 API 的后台账号会话和 RBAC；前端不再初始化 CloudBase 或保存其会话。
2. 所有后台数据操作改为 HTTPS API；接口保持当前业务语义，但服务端执行权限校验。
3. 图片上传改为“申请短期上传许可 → 直传私有 COS → API 确认绑定”的流程，数据库仅保存对象键。
4. 商品、积分商品、分类和轮播在新目录建成前显示空状态，不解析历史 `cloud://` 标识。
5. 构建产物发布到新的静态托管位置前，须在预发布环境完成登录、RBAC、上传、订单查看和历史订单展示测试。

## 未完成的发布前检查

- 后台账号和角色模型；
- 新 API 的接口契约及错误码；
- COS 短期上传/读取签名与文件校验；
- 生产 `VITE_API_BASE_URL` 的目标 API 域名和 HTTPS 联调；
- 构建产物清单、部署方式和回滚制品归档。

旧 CloudBase 静态托管和认证资源在上述检查完成、旧客户端覆盖和历史支付/售后窗口结束前不得退役。

## 目标模式补充（2026-09-16）

- 商品编辑已接入目标 API：读取 `GET /api/v1/admin/products/:id`，更新 `PUT /api/v1/admin/products/:id`。
- 图片保留采用对象键引用：服务端仅接受该商品当前已经登记的 `catalog/products/` 对象键；替换图片仍须使用当前管理员确认过的上传许可。这样不会因编辑文字、库存或履约信息而清空私有图片，也不能把其他商品的图片键绑定进来。
- 本机已通过服务端 64 项测试与目标模式前端构建；未发布，亦未访问或修改生产数据。
- 订单、退款、积分、礼品卡、优惠券、用户、剪刀 SN、售后和合作咨询仍未迁移到目标模式。其中订单、退款、积分、礼品卡与优惠券涉及支付或资金权益，须在支付入站与业务事务方案确认后实施；其余模块须在完整业务 DDL 与目标数据快照核验后实施。
