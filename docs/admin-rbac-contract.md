# 管理端 RBAC 与审计合同

更新：2026-09-10。新后台替代 CloudBase 用户名密码和浏览器直调云函数。本合同只定义权限边界，不创建管理员、角色或公网管理接口。

## 角色

| 角色 | 可做事项 | 禁止事项 |
|---|---|---|
| `catalog_editor` | 创建/编辑未发布商品、分类、轮播；申请并确认 COS 上传。 | 订单状态、库存调整、退款、积分、礼品卡、用户资料、管理员管理。 |
| `fulfillment_operator` | 查看订单、填写发货信息、处理已批准的非资金售后步骤。 | 退款审核/执行、库存和积分调整、管理员管理。 |
| `finance_reviewer` | 查看退款申请及支付对账，提交审核结论。 | 直接调用支付退款、修改订单金额、发货、角色管理。 |
| `admin` | 经二次确认执行已获批后台操作，管理角色和审计查询。 | 绕过支付验签、直接修改账本、删除审计记录、读取长期密钥。 |

所有角色都不能使用通用 SQL、任意对象键、任意 HTTP 代理或旧 CloudBase 管理会话。

## 权限映射

| 旧函数域 | 新后台资源操作 | 最低角色 | 必要审计字段 |
|---|---|---|---|
| `admin-product`、`admin-banner` | 目录草稿、发布、排序、媒体确认 | `catalog_editor` | 操作者、资源类型/内部 ID、前后状态摘要、请求 ID。 |
| `admin-order` | 订单查询、发货、售后审核、退款审核申请 | `fulfillment_operator` 或 `finance_reviewer`，按动作细分 | 操作者、订单内部 ID 摘要、动作、审批链、请求 ID。 |
| `admin-stats` | 聚合报表只读 | `admin` 或经批准运营角色 | 操作者、报表类型、时间范围、请求 ID。 |
| `admin-user`、`admin-scissors` | 当前不进入首批实现 | 无 | 需先确定业务范围和保留规则。 |

## 强制控制

1. 管理会话独立于小程序客户会话；不能通过客户端 `role`、OpenID、邮箱或前端路由推断管理员身份。
2. 退款、支付、积分、库存和礼品卡等资产动作实行职责分离：申请、审核、执行分别记录，实际支付动作还须走支付专项协议。
3. 每个写操作带服务端生成的请求 ID 与幂等键；审计记录在业务提交后写入，不记录密码、Token、完整手机号、地址、兑换码或支付材料。
4. 禁止任何“管理员万能接口”、客户端共享 secret、浏览器直连 MySQL、`mysql-api` 兼容迁移或将 CloudBase 低代码身份当作新后台身份。

## 验收用例

- 未登录、客户会话、角色不足、伪造角色字段和过期会话都必须得到 401/403。
- 目录编辑者不能读取订单或退款；履约人员不能改商品；财务审核者不能发起实际退款。
- 重复请求只保留一笔有效业务变化与对应审计记录。
- 审计检索不得返回机密或完整个人信息；管理员删除/覆盖审计记录的请求必须拒绝。
