# 第一批函数兼容合约盘点

更新：2026-09-10。范围为负责人确定的有实际调用的 14 个 CloudBase 函数。本记录仅提取本地候选源码中的 `action` 字面量，不包含请求参数、业务记录、密钥或线上制品内容。

| 函数 | 已识别 action 数 | 兼容风险 |
|---|---:|---|
| `address` | 5 | 地址写入必须由服务端会话确定用户，防越权。 |
| `admin-banner` | 7 | 管理员 RBAC、排序和媒体键校验。 |
| `admin-order` | 12 | 发货、退款审核和微信发货动作必须拆分权限与审计。 |
| `admin-product` | 6 | 新目录为空，新增/补货流程需适配重新上传策略。 |
| `admin-stats` | 1 | 统计口径需与新空目录和历史订单分离。 |
| `banner` | 0 | 需从函数返回结构补齐无 action 的读取合约。 |
| `category` | 2 | 新分类由后台重建；读取接口先兼容空集。 |
| `coupon` | 4 | 两份本地源码 action 不一致，且旧券规则待业务确认。 |
| `giftCard` | 10 | 兑换码唯一性、管理员操作和地址确认需事务/审计。 |
| `login` | 0 | 需从函数返回结构补齐微信 code 与会话合约。 |
| `order` | 23 | 订单、积分订单、退款、库存与支付状态动作需拆分并幂等。 |
| `product` | 6 | 新目录读取与历史订单快照必须解耦。 |
| `scissors` | 12 | 两份本地源码的售后 action 不一致，需线上制品核验。 |
| `user` | 5 | 用户资料和积分只能由会话身份访问。 |

## 已确认的本地差异

- `coupon`：E 盘版本额外包含 4 个优惠券 action；两份源码不能混用。
- `scissors`：D 盘版本额外包含 8 个售后 action；两份源码不能混用。
- 其他有双份源码的首批函数在 action 名称层面一致，但仍不等于线上制品相同。

## 下一步

在为 `coupon`、`scissors` 生成新 API 合约或实现前，必须取得安全的线上制品标识或受控源码比对结果。支付相关功能仍单独最后处理。
