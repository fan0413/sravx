# SRAVX 项目展示与技术复盘

更新日期：2026-10-14。本文用于面试演示和代码阅读，不包含账号、真实用户/订单资料或生产凭据。

## 项目定位

这是围绕宠物美容工具真实运营需求持续迭代的电商项目：品牌官网负责展示，小程序承载用户场景，管理端维护商品与运营内容，服务器提供统一业务事实。目标是减少重复录入和跨端数据不一致，而不是仅制作几个静态页面。

开发过程中使用AI辅助实现与排查。面试时应如实说明自己实际参与的需求定义、方案选择、代码理解和验收工作，不将工具生成量表述为独立手写量，不虚构团队规模、用户量或营收。

## 五分钟演示路线

1. 打开https://sravxpet.com，展示鼠标拖动、当前产品识别、信息展开、触摸/键盘及暂停。说明展示组件仅进入H5，不增加小程序资源包。
2. 点击“进入官网”，介绍保留的品牌演示内容；从产品导航进入系列目录，查看真实后端商品、最低规格价格与商品选配详情，刷新验证路由。
3. 打开仓库，沿README架构图定位前端共享适配、管理端和服务器仓储。不要给面试官生产后台账号，管理端演示使用本地合成API或脱敏截图。
4. 选一个难点展开：分类建模、媒体过期处理、接口迁移或支付幂等。用源码和测试解释约束，不现场操作真实退款。
5. 结束时展示测试/发布证据，主动说明网页登录和完整网页交易仍未验收，以及代码库私有访问、真机验收和后续工程化计划。

## 可以展开讨论的工程问题

### 1. 多端商品一致性

问题：分类、规格价格和媒体字段分散时，管理端保存成功不代表两个客户端正确展示。

做法：商品主体共用，分类使用明确系列/剪型及关联表；服务端统一公开目录，前端共用分类、价格和选配解释。展示最低规格价格，缺失价格或库存不自动补成可购买。

取舍：不按Basic/Pro/Master/配件拆四张商品表，减少查询与订单引用分叉；类型差异用约束及字段适用规则表达。既有兼容代码按日期保留，不做未经验证的批量删库。

代码入口：`server/src/catalog/`、`server/src/repositories/mysql-catalog-repository.js`、`server/migrations/013_catalog_classifications.sql`、`sravx/common/product-classification.mjs`、`sravx/common/product-price.mjs`。

### 2. 私有媒体与临时地址

问题：永久公开对象与前端长期保存签名链接都有风险；临时链接过期会导致图片失效。

做法：保存对象引用，仅为可见目录引用生成临时URL；前端识别媒体到期后重新读取商品。上传许可、对象确认与展示读取分开，避免匿名任意对象签名。

取舍：暂不引入未配置的CDN；关注正确读取与权限边界，不能声称已经实现全球加速或长期缓存。

代码入口：`server/src/media/public-catalog.js`、`sravx/components/SravxProductPurchaseH5.vue`、对应`public-catalog-media`和`web-product-contract`测试。

### 3. 服务迁移与安全边界

问题：旧云环境失效后仍有页面调用旧函数，跨域配置也可能让登录和目录读取看起来像随机故障。

做法：集中接口适配，服务器成为当前业务入口；管理端同域请求保留会话认证，官网只代理公开目录且不转发Cookie/Authorization。接口失败明确报错，不回退另一份商品事实源。

取舍：源代码中保留旧系统供追溯，但不代表运行时仍使用；代码同步、API部署、官网上线和小程序发布分别验收。

代码入口：`sravx/common/api.js`、`sravx/common/catalog-transport.mjs`、`admin-web/src/lib/target-admin-auth.ts`、`deploy/nginx/sravx-web-public.conf`。

### 4. 交易状态与幂等

问题：支付通知、退款请求及网络重试可能重复；接口接受退款不代表资金已退回。

做法：服务端确定金额与库存，回调先验签并持久化入站，再幂等结算。退款区分审核、执行、处理中和最终结果；客户端不把接受状态显示成退款完成。

取舍：这是有源码和自动测试的交易实现，不宣称已验证所有支付渠道、金融级可用性或完整网页交易。生产资金操作需单独授权。

代码入口：`server/src/payments/payment-event-consumer.js`、`server/src/repositories/mysql-payment-settlement-repository.js`、`server/test/payment-settlement.test.js`、`server/test/unshipped-refund.test.js`。

### 5. 展示动画与交付可核验

问题：动画做出来不等于当前款清晰、鼠标/触摸操作正确，构建成功也不等于服务器实际部署一致。

做法：将展示几何作为纯函数测试，交互捕获指针并区分拖动/点击，支持取消、减少动画与卸载清理；浏览器覆盖桌面/窄屏。发布独立静态制品、逐文件核对摘要，启用HTTPS并演练自动续期。

取舍：目前是集中组件与轻量测试脚本，没有宣称已建立自动CI/CD、性能基准或完整无障碍认证；后续可拆分动画控制状态并加入自动化流水线。

代码入口：`sravx/components/ScissorOrbitH5.vue`、`sravx/common/scissor-orbit.mjs`、`sravx/scripts/verify-scissor-orbit.cjs`、`sravx/scripts/verify-public-web-release.mjs`。
