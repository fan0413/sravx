# 源端调用方静态核验

更新：2026-09-10。范围为小程序、管理端源码和本地云函数源码的静态字面引用。该核验不包含旧客户端、动态函数名、低代码运行时、支付平台回调、日志或网络流量，不能作为退役证明。

## 结果

- 30 个线上函数中，23 个在小程序或管理端源码中发现了字面引用。
- 未发现直接小程序/管理端引用的函数：四个低代码函数、`wxpayFunctions`、`mysql-api`、`scissors-admin`。
- 静态扫描还发现若干非当前线上函数清单中的直接函数名，说明存在封装、测试或历史调用痕迹；不能将其忽略。
- 本地源码中发现 CloudBase Run/`payment-api` 相关引用，但静态文本不能确定运行时域名、具体调用方或回调来源。

## 处置含义

| 范围 | 当前结论 | 后续关闭条件 |
|---|---|---|
| 目录、用户、订单、优惠券、礼品卡、剪刀与后台函数 | 有静态调用证据，且部分在 7 天监控窗口有调用。 | 新 API 合约、身份权限和回归测试通过后才能迁移调用方。 |
| 支付、物流与 CloudBase Run `payment-api` | 存在本地引用或独立线上流量。 | 支付/物流调用方、回调来源、验签、入站持久化和幂等演练完成。 |
| 四个低代码函数与 `wxpayFunctions` | 未发现静态前端/后台引用。 | 低代码负责人、支付集成、线上制品和更长观察期均确认后才可处置。 |
| `mysql-api`、`scissors-admin` | 未发现静态前端/后台引用。 | 旧客户端、后台制品、调用日志和负责人确认无依赖后，才可退役。 |
