# 新 API 兼容回归优先级

依据：2026-09-03 至 2026-09-10 的 CloudBase 云函数调用汇总。该指标用于排列测试优先级，不代表销量、用户数或函数可退役性。

## P0：先完成兼容与权限测试

| 业务域 | 7 天有调用的旧入口 | 新服务验证重点 |
|---|---|---|
| 商品目录 | `product`、`category`、`banner` | 空目录重建期间的返回结构、分页、媒体键拒绝规则和维护提示。 |
| 登录与用户 | `login`、`user`、`address` | 微信身份换取、服务端会话、地址越权与匿名入口处理。 |
| 订单与权益 | `order`、`coupon`、`giftCard` | 幂等、库存/积分事务、旧券隔离、礼品卡唯一性与历史事实展示。 |
| 剪刀与保修 | `scissors` | SN 唯一性、用户权限、历史售后关联。 |

## P1：后台回归

`admin-product`、`admin-banner`、`admin-order`、`admin-stats` 在同一窗口仍有调用。新后台上线前须完成管理员 RBAC、审计、目录重建、历史订单展示和统计口径验证。

## 仍需保留观察的入口

负责人已决定不将 7 天零调用的 16 个函数纳入第一批新 API 重写。它们仍不能立即退役，特别是 `paymentProxy`、`sf-express`、`wxpayFunctions`、四个低代码函数、`mysql-api` 与 `scissors-admin`，必须在调用方、制品、支付/物流或低代码依赖核验完成后，才能最终停用。

## 测试原则

- 测试使用脱敏数据或隔离恢复库，禁止对生产订单、库存、积分、支付和退款双写。
- 支付回调必须分别验证验签失败、重复、乱序、超时重试和退款回调。
- 目录主数据重新上传后，历史订单页面只显示快照，不自动跳转到新商品。
