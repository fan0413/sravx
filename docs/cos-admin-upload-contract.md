# 新目录 COS 上传合同

更新：2026-09-10。适用于负责人重新上传商品、积分商品、分类和轮播图片。当前私有 COS 桶与内部 API 已准备，但本合同不启用上传接口、不复制旧 CloudBase 对象。

## 基本规则

1. 小程序和后台不持有 COS 长期密钥；只从受 RBAC 保护的 API 获取短时、单对象、限定前缀的上传凭据或受控上传 URL。
2. 每次上传服务端生成对象键，客户端不能指定任意 bucket、对象键、Content-Type、缓存策略或 ACL。
3. 新目录只允许以下前缀：`catalog/products/`、`catalog/points-products/`、`catalog/categories/`、`catalog/banners/`。
4. 目录表只保存受控对象键，禁止保存 `cloud://`、CloudBase 临时 URL、COS 临时 URL、任意 `http(s)` URL 或本地文件路径。
5. 上传成功不等于目录发布：后台应先完成媒体元数据校验，再把对象键写入商品/分类/轮播记录。未引用的上传对象进入受控清理队列，清理动作需单独确认。

## 上传 API 设计

| 接口 | 身份 | 输入 | 输出 | 约束 |
|---|---|---|---|---|
| `POST /api/v1/admin/media/upload-intents` | 管理员 RBAC | 业务类型、文件名、MIME、大小、内容摘要 | 受限上传意图、对象键、过期时间 | 只允许图片白名单和大小上限；不回传长期密钥。 |
| `POST /api/v1/admin/media/confirm` | 管理员 RBAC | 上传意图 ID、对象键、内容摘要 | 媒体元数据 | 校验对象确属该意图、大小/MIME/摘要匹配。 |
| `GET /api/v1/media/{key}` | 按资源可见性 | 受控对象键 | 短期下载/展示 URL 或代理内容 | 私有桶；订单历史与后台媒体按权限分开。 |

## 验收与安全

- 管理员、普通小程序用户、未登录用户和伪造对象键分别测试，后三者均不得取得上传意图。
- 伪造前缀、超时意图、MIME 与文件内容不符、大小超限、重复确认、跨管理员确认必须拒绝并审计。
- 上传与确认日志只记录意图 ID、对象键摘要、结果与操作者内部 ID；不记录长期密钥、签名串、请求体或图片二进制。
- 商品删除或媒体替换不自动删除 COS 原对象，避免历史订单或售后引用丢失；清理前先执行引用扫描并获得负责人确认。

## 未放行项

- 管理员 RBAC、短期会话账本、COS 上传意图存储、对象内容校验与新后台改造均未实现。
- 在这些项完成前，不能把私有 COS 对象直接暴露给小程序，也不能开放目录上传。
