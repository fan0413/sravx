# 小程序后端 API 契约：实施任务

- [ ] 1. 完成目标 API 身份层
  - 建立微信 code 换取服务端会话、刷新与撤销机制。
  - 所有写接口从 Bearer Token 解析用户，移除客户端身份字段。
  - _Requirement: 2, 3_

- [ ] 2. 建立商品 SKU 与颜色模型
  - 将现有 `product_specs` 迁移或映射为型号层，新增颜色与 SKU 组合的受控数据模型。
  - 通过管理端维护型号、颜色、SKU、价格、库存和媒体用途。
  - _Requirement: 1, 3, 7_

- [ ] 3. 实现商品详情与报价 API
  - 商品详情返回可售选配组合，报价接口由服务端计算价格与库存并签发短时 `quoteId`。
  - 小程序替换本地价格计算，使用 `skuId` 与 `protectOfferId` 发起报价。
  - _Requirement: 1, 2_

- [ ] 4. 实现 SRAVX Protect 配置与权益链路
  - 建立计划、报价、订单快照和绑定后权益记录。
  - 未通过审核的计划不得暴露为可购买选项。
  - _Requirement: 4, 5, 6, 7_

- [ ] 5. 改造订单与支付写链路
  - 创建订单只接收报价单和地址，事务写入订单项及服务项快照。
  - 支付回调先验签、持久化入站事件，再幂等消费业务变更。
  - _Requirement: 3, 4_

- [ ] 6. 改造购物袋与确认订单前端调用
  - 保留本地购物袋体验，结账时将型号、颜色与 Protect 转换为服务器 SKU/offer 报价。
  - 首期保持单件结账，待订单模型支持后再设计多件合并结账。
  - _Requirement: 2, 3_

- [ ] 7. 回归与迁移演练
  - 覆盖价格篡改、库存竞争、过期报价、重复下单、重复回调、SN 重复绑定、计划不适用和未授权访问。
  - 按迁移计划完成写链路演练与放行证据，不进行长期双写。
  - _Requirement: 1, 2, 3, 4, 5, 6, 7_
